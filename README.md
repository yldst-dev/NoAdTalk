# NoAdTalk

카카오톡 Mac 기본 창의 하단 광고와 광고 공간을 숨깁니다. 친구, 채팅, 더보기 화면이 대상입니다. 실행 파일을 바꾸거나 재서명하지 않고 `FSMainViewController.nib`의 광고 연결과 높이 제약만 수정합니다.

## 시작하기

1. [최신 릴리즈](https://github.com/yldst-dev/NoAdTalk/releases/latest)에서 `NoAdTalk.zip`을 내려받아 압축을 풉니다.
2. `NoAdTalk.command`를 더블클릭합니다.
3. **적용 및 자동 감지 켜기**를 선택하고 **실행**을 누릅니다.
4. 카카오톡 종료 확인과 관리자 인증이 나타나면 진행합니다. 암호는 열린 터미널에 입력하며 화면에는 표시되지 않습니다.

처음 설정한 뒤에는 같은 파일에서 적용 상태와 자동 감지 상태를 확인하고 모든 기능을 관리할 수 있습니다. 관리자 인증은 macOS에서 요구하는 절차이므로 생략하지 않습니다. 외부 앱이나 패키지를 자동 설치하지 않습니다.

Python 3가 필요합니다. macOS의 `/usr/bin/python3`를 사용하며 외부 Python 패키지는 설치하지 않습니다. Python이 없는 환경에서는 Apple Command Line Tools가 필요할 수 있습니다.

### 관리자 인증 후에도 변경이 막힐 때

`Operation not permitted`가 나타나면 **시스템 설정 → 개인정보 보호 및 보안 → 앱 관리**에서 **터미널**을 켜 주세요. 다른 터미널 앱에서 실행했다면 해당 앱을 허용합니다. macOS가 터미널을 다시 열도록 안내하면 진행한 뒤 `NoAdTalk.command`에서 같은 작업을 다시 실행합니다. 관리자 암호와 앱 관리 권한은 별개입니다. [Apple의 앱 관리 안내](https://support.apple.com/en-au/guide/mac-help/mchl211c911f/mac)를 참고해 주세요.

적용과 복구 모두 카카오톡을 종료하기 전에 앱 폴더에 임시 파일을 만들고 지울 수 있는지 검사합니다. macOS가 생성을 차단하면 설정 화면을 열고 작업을 중단하므로 현재 화면과 자동 감지 설정은 유지됩니다. 전체 디스크 접근 권한을 켜거나 시스템 보호를 끌 필요는 없습니다.

## 관리 메뉴

| 메뉴 | 동작 |
|---|---|
| 적용 및 자동 감지 켜기 | 광고 숨김 적용 후 업데이트 감지를 등록합니다. 처음 사용할 때 선택합니다. |
| 광고 숨김만 적용 | 감지 설정을 바꾸지 않고 현재 앱을 패치합니다. |
| 원래 화면 복구 및 자동 감지 끄기 | 현재 버전의 원본을 복구한 뒤 감지를 해제합니다. |
| 자동 감지만 켜기 | 로그인 시와 300초마다 설치된 앱을 확인합니다. |
| 자동 감지만 끄기 | 감지만 해제하고 광고 숨김과 원본 백업을 유지합니다. |
| 상태 확인 | 현재 광고 숨김과 자동 감지 상태를 표시합니다. |

원본은 `~/Library/Application Support/NoAdTalk/<버전>-<빌드>/FSMainViewController.nib`에 보관합니다. 이미 적용됐다면 다시 수정하지 않으며, 다른 버전의 백업으로 복원하지 않습니다.

## 업데이트 자동 감지

새 화면 파일이 설치되고 패치할 수 있는 구조인지 확인되면 적용 안내가 나타납니다. **적용**을 선택하면 터미널이 열리고 관리자 인증과 앱 종료 확인 후 패치합니다. 암호를 저장하지 않으며 감지 프로그램은 일반 사용자 권한으로 실행됩니다. App Store에서 새 버전을 내려받거나 설치하지는 않습니다.

같은 버전과 파일에 대한 안내는 1번만 표시합니다. 안내를 닫았거나 인증을 취소했다면 관리 메뉴의 **광고 숨김만 적용**으로 다시 진행할 수 있습니다. 서명이나 구조 검사를 통과하지 못한 파일은 수정하지 않습니다. 수동 실행 시 중단 이유를 확인할 수 있습니다.

감지 파일은 `~/Library/Application Support/NoAdTalk/Agent`에 복사하고, `~/Library/LaunchAgents/local.no-ad-talk.watcher.plist`에 등록합니다. 압축을 푼 폴더를 옮겨도 동작합니다. 감지가 켜져 있는 동안에는 해당 `Agent/NoAdTalk.command`에서도 관리할 수 있습니다.

새 NoAdTalk 릴리즈를 내려받았다면 새 폴더의 관리 메뉴에서 **자동 감지만 켜기**를 다시 실행해 설치된 스크립트를 갱신합니다. 이전에 나뉘어 있던 적용·복구·감지 실행 파일은 `NoAdTalk.command`로 통합됐으며 기존 백업은 유지됩니다.

## 버전 대응과 한계

버전 번호, 고정된 바이트 위치나 파일 해시로 새 버전을 차단하지 않습니다. NIBArchive에서 `advertiseContainerView`, `advertiseContainerHeightConstraint`, `adSeparatorHeightConstraint` 연결을 찾아 같은 컨트롤러와 올바른 높이 제약을 가리키는지 검사합니다. 광고 컨테이너 연결을 nil로 바꾸고 높이를 0, 숨김을 true로 설정합니다. 연결이 없거나 중복되거나 지원하지 않는 형식이면 파일을 변경하지 않습니다.

실제 광고 제거는 카카오톡 `26.9.0`, 빌드 `2006`, macOS `27.2`에서 확인했습니다. 새 버전의 nib 구조가 같아도 앱의 실행 코드가 달라질 수 있으므로 모든 미래 버전의 동작을 보장하지는 않습니다. 적용 후 실제 화면을 확인해 주세요. 이전 고정 위치 패치의 백업도 그대로 사용할 수 있습니다.

화면 파일을 바꾸면 앱 전체의 리소스 서명 검사는 실패합니다. 실행 파일의 원래 서명은 유지하지만, macOS에서 실행을 막거나 업데이트가 영향을 받을 수 있습니다. 시험 중 수정한 앱 복사본은 손상 경고로 막혔으며 기존 설치 경로에 nib만 적용한 경우 정상 실행됐습니다. 스크립트는 실행이 바로 실패하면 복구를 시도하지만, 프로세스가 살아 있는 채 실행이 막히는 경우까지 감지하지는 못합니다.

네트워크 광고 요청 차단, 잠금 화면이나 다른 창의 광고 제거는 보장하지 않습니다. 자동 감지는 App Store에서 새 버전을 내려받거나 설치하지 않습니다.

## 개발과 배포

`bash test.sh`는 설치된 앱과 원본 백업을 이용해 복사본에서 적용·복구·이전 패치 전환을 검사합니다. 현재 회귀 검사의 기준 파일은 `26.9.0-2006`입니다. 객체 번호와 속성 순서를 바꾼 nib도 실제 AppKit으로 로드해 검사하며, 잘못된 입력 거부와 감지 등록·해제와 관리 작업 순서, 취소 시 무변경을 테스트합니다. `27.1.0-3000`은 버전별 처리 검사용 가상 값이며 해당 버전의 실제 앱을 시험했다는 뜻이 아닙니다. 이 가상 버전 검사에서만 서명 검사를 대체합니다. 설치된 앱은 변경하지 않습니다. 테스트에는 Apple Command Line Tools가 필요합니다.

터미널에서는 `bash NoAdTalk.command status`로 상태를 확인할 수 있습니다. `setup`, `apply`, `restore`, `enable`, `disable` 인수도 같은 관리 작업을 실행합니다.

`bash build.sh`는 `dist/NoAdTalk.zip`을 만듭니다. 배포 파일과 캐시, Finder 메타데이터는 커밋에서 제외합니다.
